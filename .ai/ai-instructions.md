# AI Instructions

Meta-rules for any AI coding agent (Claude Code, Copilot, Cursor, others) working in this repo.

## Read first, per task type

| Task | Read before coding |
|---|---|
| New feature | [specs/index.md](../specs/index.md), [specs/templates/feature-spec.md](../specs/templates/feature-spec.md), [.ai/architecture-summary.md](architecture-summary.md) |
| Bug fix | [specs/templates/bugfix-spec.md](../specs/templates/bugfix-spec.md) (for non-trivial fixes), [.ai/testing-strategy.md](testing-strategy.md) |
| Refactor | [specs/templates/refactor-spec.md](../specs/templates/refactor-spec.md), relevant ADRs in [docs/adr/](../docs/adr/) |
| Architecture/API/MQTT/hardware/config change | matching spec **and** an ADR — see trigger table below |

## Spec-and-ADR-first rule

A change is **architecturally significant** if it touches any of: task chain/RTOS structure, manager responsibilities, the device data-model shape, REST API surface, MQTT topic structure, config persistence format, or hardware abstraction. For these:

1. Check [specs/index.md](../specs/index.md) and [docs/adr/README.md](../docs/adr/README.md) for existing coverage.
2. Write/update a spec from [specs/templates/](../specs/templates/) before implementing.
3. Write/update an ADR from [docs/adr/templates/adr-template.md](../docs/adr/templates/adr-template.md) if the decision itself changed (not just its implementation).
4. After implementing, update [docs/architecture/repository-map.md](../docs/architecture/repository-map.md) and [.ai/architecture-summary.md](architecture-summary.md) if they now describe stale behavior.

Purely local bug fixes and non-architectural features do not require an ADR.

## Hard constraints

- Never edit `software/lib/*` (vendored third-party libraries).
- Never hand-edit `main/webroot/*_gz.h` (generated by `build_script.py`) — edit `main/webroot_source/` and regenerate.
- Preserve the logic/routing split in `main/api/` (see [.ai/common-patterns.md](common-patterns.md) #3).
- Preserve the data-table device model in `main/ithodevice/` (see [.ai/common-patterns.md](common-patterns.md) #2).
- Don't introduce `xQueueCreate`-based messaging without an ADR — the current flag-polling pattern is a deliberate baseline (see [docs/adr/ADR-0004-freertos-linear-task-chain.md](../docs/adr/ADR-0004-freertos-linear-task-chain.md)).

## Don't duplicate documentation

If information already lives in `docs/architecture/repository-map.md` or an `.ai/*.md` file, link to it — do not restate it in a new doc, PR description template, or comment block.
